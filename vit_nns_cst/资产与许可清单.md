# NNS-CST N0 资产与许可清单

日期：2026-09-22  
阶段：N0  
盘点方式：仅文件元数据、已封存清单、ZIP central directory 和流式字节哈希  
裁定：`DATA_FEASIBLE`

## 1. 结论

本地资产足以为 N1/N2 构造一个严格审计的前景/背景配对反事实 pilot：有 ImageNet 原图、ImageNet-S919 外部前景 mask、source-level 独立拆分、1000 类冻结分类头映射、ViT-B/16 与 DeiT-S/16 checkpoint，以及已实现的 ViT target、complete-cut、JVP/VJP 和 intervention 基础设施。

当前**没有**现成的背景语义标签、donor registry、编辑图、null edit 或 pair 质量结果。因此 `DATA_FEASIBLE` 表示“资产和许可允许按预先冻结的规则构造并审计 pairs”，不表示 pairs 已存在、编辑质量已通过或 N2 测量可行性已经成立。若 N2 不能生成同时通过语义、几何、低级强度与伪影质检的 semantic/null pairs，必须改判 `NO_GO_NOT_IDENTIFIABLE`，不能把自然图的非配对差异当替代品。

许可边界是本地、非商业研究使用。ImageNet-S 上游审计没有找到明确 annotation license；本项目依据 2026-09-14 的用户授权声明继续本地研究，但不由此推断再分发、公开上传、商业使用或第三方许可。模型 checkpoint 的文件身份已知，权重级许可未在既有 registry 中形成独立凭据；在对外分发或商业使用前必须另行核验。

## 2. 本轮访问边界

本轮执行并核对了以下约束：

- 未下载任何数据或模型；
- 未读取或解码 JPEG/PNG payload；ZIP 检查仅读取 central directory；
- 未反序列化 checkpoint，未导入 Torch/timm，未加载模型；
- 未使用 GPU/CUDA，未训练、推理、运行 NNS 或 activation patching；
- 未读取 confirmation outcome；
- 对大文件仅做流式 SHA-256，哈希值是当前字节身份，不是许可或科学有效性证明。

### 3.1 当前 manifest 的完整性事实

- 10,464/10,464 image references 当前存在。
- 10,464/10,464 mask archive references 当前存在。
- 10,463 个唯一 annotation hashes 意味着有一组 mask bytes alias。它不合并不同 source identity，但未来任何生成谱系仍必须按 source group 绑定，不能用 mask hash 代替 source identity。
- 872 个 target model class indices 全部非空；可作为 ImageNet-1k classifier head 的映射候选。映射正确性是既有 metadata 证据，N1/N3 仍需绑定具体 label file、checkpoint 和 preprocessing。
- public-validation confirmatory holdout 已由既有 route contract 冻结：不得用于 pilot、超参数或 endpoint 选择，也不得为样本选择查看图像/mask。N0 没有打开它。

## 4. 配对谱系合同的最低字段

N0 不生成 pair，但判定可行性依赖下一阶段把每一个原图、donor 和派生版本绑定在同一生成谱系中。最低字段如下，N1/N2 schema 必须 closed：

| 字段 | 含义与规则 |
|---|---|
| `pair_id` | 不含 outcome 的稳定 ID |
| `source_group_id` | 原图以及所有 crop、重编码、背景替换、语义编辑版本共享同一 group |
| `recipient_source_id` / `recipient_sha256` | 保留前景或背景的原始 source 与 bytes |
| `donor_source_id` / `donor_sha256` | 被移植因素的 source 与 bytes；不得跨 exposure 边界污染 confirmation |
| `mask_id` / `mask_sha256` | 外部 mask 身份，记录 bytes alias 但不以其替代 source group |
| `semantic_axis` / `semantic_label_source` | 前景、背景、一致/冲突的冻结定义及人工/外部标签来源 |
| `edit_type` | `semantic_background_swap`、`semantic_foreground_swap`、`null_render` 或其他预注册有限枚举 |
| `producer_id` / `producer_version` | 合成算法、插值、颜色/边界处理、随机种子和参数 |
| `edit_region_digest` | 改动区域坐标或 mask 的身份 |
| `low_level_metrics` | 改动像素数、$L_1/L_2$、色彩、频谱、边界强度、压缩/渲染统计；定义先于 outcome |
| `split` / `use_policy` | engineering、pilot、validation、confirmation、replication；所有 lineage 成员同组分配 |
| `exposure_state` | 是否看过图像、NNS、probe、layer、intervention 或模型 outcome；一旦暴露不可逆降级 |
| `quality_status` | 独立 reviewer/validator 对语义保真、几何、融合和伪影的裁定，不能由 producer 自报 |

## 8. 去重与 outcome 隔离

1. 独立单位固定为 `source_group_id`，不是编辑文件、mask 或 token。
2. recipient、donor 以及所有派生图的 source IDs 都参与 split 分组；任一祖先或 donor 暴露会使整个生成 group 失去 confirmation/replication 资格。
3. 历史 1,101 个 source exclusions 和 Endpoint、PCIA-PEFA、Stage C/D/E/F/X/Y 等 exposure ledger 必须取并集。
4. 不能只做文件路径去重；必须同时比较 canonical source ID、原始 image SHA-256 和已知 lineage。
5. annotation byte alias 不代表 image alias，但必须记录；跨 official split 的 byte alias 继续隔离。
6. confirmation pair 的 donor 也不得来自 pilot、validation 或历史 outcome-known source。
7. replication 不得复用 discovery/confirmation 的 recipient、donor 或其任何派生版本。

## 9. `DATA_FEASIBLE` 裁定条件

`DATA_FEASIBLE = true`，依据是原图、外部 mask、类别映射、足量 source-level pools、两个模型 checkpoint 和实现基础均真实存在，且本地研究使用有明确用户授权记录。该门不授权 N1，也不承诺 N2 成功。继续成立需要：

- N1 生成 closed pair/lineage schema 和独立 validator；
- N2 仅在隔离 pilot 上生成 semantic edit 与同强度 null edit；
- background semantics 在 outcome-blind 条件下由外部规则或人工标注冻结；
- pair quality 和 low-level matching 由独立 validator 重算；
- 任一许可范围扩大、外发或商用前重新审计。
