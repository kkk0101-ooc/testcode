# NNS-CST：因果语义子空间传输执行规划

日期：2026-09-22

状态：`PROPOSED_NOT_FROZEN / NOT_AUTHORIZED / NOT_RUN`

研究问题、数学对象和结论边界以[研究目标](研究目标.md)为准。

## 1. 当前授权与总路线

本轮只建立研究目录和两份设计文档。没有授权数据下载、图像解码、模型加载、子空间训练、GPU 使用、正式实验或既有项目结果改写。

NNS-CST 使用独立命名空间和独立证据根，不作为 `vit_pcia_pefa` 的恢复阶段，也不修改 `vitnns_rebuild` 中已封存的 Endpoint/NNS 结果。建议阶段如下：

```text
N0 相关工作、资产和可识别性审计
 -> N1 数学合同、实现骨架和解析测试
 -> N2 隔离 pilot 与测量可行性
 -> N3 正式协议、cohort、统计和预算冻结
 -> N4 discovery/validation 子空间学习与 confirmation seal
 -> N5 held-out 表征确认和 NNS 输入/贡献生产
 -> N6 子空间注入、擦除和模块传输干预
 -> N7 CPU-only 统计、独立审计和逐主张裁定
 -> N8 独立模型复现、工具交付和论文定位
```

每阶段必须验证前驱，完成后停在下一显式授权门。基础设施或数值问题只能在 fresh root 中恢复；科学阴性不能通过换概念、换层、换秩、换阈值或追加样本来恢复。

## 2. 全阶段共同规则

### 2.1 研究与证据边界

1. 证据顺序固定为 `representation -> contribution -> intervention -> replication`。
2. Endpoint 仅作为内部标量的 Gradient × Input 快速扫描，不作为新基础算法。
3. Path NNS 与 complete-cut NNS 使用现有定义；新增的是语义子空间对象和传输问题。
4. 单 head、单 channel、probe 准确率或热图外观不能单独支持语义机制。
5. 形式闭合是正确性证据，不是语义发现。
6. confirmation outcome 读取后，不再改变主概念、模型、层、rank、metric、阈值、统计单位或主对照。
7. 每项 claim 独立裁定；workflow complete 不等于 scientific support。

### 2.2 数据隔离

数据至少分为：

- `engineering_fixture`：合成输入和无科学解释的代码测试；
- `pilot_discovery`：允许查看，用于选择有限配置；
- `validation`：只用于冻结超参数，不用于正式效应估计；
- `confirmation`：读取前签发不可变 seal；
- `replication`：第二模型或第二架构，独立于前述选择。

所有拆分按 source image 和生成谱系去重。同一原图的裁剪、重编码、背景替换和语义编辑版本属于同一 group，不能跨 split。任何看过 NNS 图、probe 输出、层效应或 intervention 结果的样本永久退出 confirmation 和 replication。

### 2.3 文件与终态规则

未来产物统一置于本目录，建议结构为：

```text
vit_nns_cst/
  研究目标.md
  执行规划.md
  config/
  manifests/
  src/
  tests/
  evidence/<stage_root>/
  reports/<report_root>/
```

- `config/` 和 `manifests/` 使用 closed schema，嵌套对象不得以开放 `payload` 代替具体字段。
- 权威数值保存在 `evidence/`，可浏览图和文字保存在 `reports/`。
- terminal root 不原地修改；恢复必须引用前驱 root、失败类型和继承内容。
- 哈希用于数据、代码和关键合同绑定，不为普通说明文字堆叠无意义 digest。
- producer 与 validator 分离；validator 从原始记录重算，不能只读取 producer 的 `PASS`。

### 2.4 资源与调度

- wall time 和 GPU-hours 用于规划和优化，不作为科学失败门，除非运行明显违反预算或合同。
- 多 GPU 生产默认使用全局动态队列、长驻 worker 和原子 claim，不做静态 `index % K` 分片。
- GPU 按空闲显存和利用率门槛选择，并记录已有 PID；不要求设备绝对空闲。
- `CUBLAS_WORKSPACE_CONFIG` 必须在任何 Torch/CUDA import 前设置；启动 probe 包含矩阵乘法和 backward。
- CPU-only 阶段显式清空 `CUDA_VISIBLE_DEVICES`，不得加载模型或解码未授权图像。

## 3. N0：相关工作、资产与可识别性审计

### 3.1 目标

在不开始模型计算的条件下回答三个问题：

1. 候选创新是否已被现有 concept circuit、SAE、CAV 或 activation-patching 方法覆盖；
2. 本地是否有足以构成严格配对反事实的数据、mask、模型和许可；
3. 前景/背景语义因素是否能与低级像素变化、类别变化和生成伪影分离。

### 3.2 文献审计

至少覆盖以下方法族，并记录正式来源、方法对象、数学式、代码可用性、数据规模、验证方式和与 NNS-CST 的重叠：

- TCAV/CAV 及 concept bottleneck/probe；
- network dissection、feature visualization 和 neuron attribution；
- sparse autoencoder、PatchSAE、transcoder/crosscoder；
- activation patching、causal tracing、causal mediation；
- ACDC、edge attribution、ViT circuit discovery；
- Prisma、ViSAE 及视觉 concept circuit；
- IG/conductance、GlobEnc、DecompX、AttnLRP、ALTI、LibraGrad；
- NNS、NNS-ViT Endpoint 和 complete-cut path conductance。

审计必须给出“已有工作已经做了什么”和“NNS-CST 仍需证明什么”。若候选方法只是现有方法的直接组合且没有新的可验证性质，则终态为 `NO_GO_NOVELTY`。

### 3.3 数据与模型盘点

只读元数据，不解码正式图像：

1. 盘点具有前景 mask、背景标签或受控组合关系的数据集；
2. 记录原始图、mask、编辑图、donor 和生成过程的谱系；
3. 检查类别与冻结分类头的映射；
4. 与 PCIA-PEFA、Endpoint、NNS 及其他历史 cohort 做 source-level 去重；
5. 盘点 DeiT-S/16、ViT-B/16 或其他候选模型的真实 checkpoint、许可和已有 adapter；
6. 盘点可复用的 NNS target registry、complete-cut、JVP/VJP 与 intervention 代码，但不把可复用代码等同于科学可继承结果。

### 3.4 可识别性检查

对 primary 前景/背景问题写出因果对比表：

| 对比 | 保持不变 | 改变 | 主要混杂 |
|---|---|---|---|
| 同前景、换背景 | 前景像素/几何、目标类别 | 背景语义 | 边界融合、全局颜色 |
| 同背景、换前景 | 背景 | 物体语义 | 物体面积、位置、遮挡 |
| 一致/冲突背景 | 前景与类别 | 上下文一致性 | 数据集先验、编辑质量 |
| null edit | 语义 | 压缩或渲染细节 | 编辑管线伪影 |

若无法构造至少一个“语义变化”和一个“同强度非语义变化”对照，终态为 `BLOCKED_IDENTIFIABILITY`。

### 3.5 N0 交付与准入

建议交付：

- `相关工作与新颖性矩阵.md`；
- `资产与许可清单.md`；
- `配对反事实可识别性审计.md`；
- `n0_decision.json`。

N0 只有在 `NOVELTY_CANDIDATE`、`DATA_FEASIBLE` 和 `IDENTIFIABLE` 均成立时才允许申请 N1。N0 不下载数据、不训练、不推理、不看正式 outcome。

## 4. N1：数学合同、实现骨架和解析测试

### 4.1 冻结计算图对象

为每个模型注册：

- patch embedding 后的 token residual stream；
- 每个 block 的 pre/post LayerNorm；
- attention 的每个 head 输入、value、pre-projection output、merged output 和 residual use-edge；
- MLP expand、activation、contract output 和 residual use-edge；
- CLS、final norm、classifier margin。

端口身份采用 producer tensor、consumer operator、input slot、invocation index、block、branch 和 checkpoint 联合定义。不能只依赖模块名和 hook 顺序。

### 4.2 冻结子空间接口

实现前先写定：

- 激活张量布局和 token 集合；
- 配对差异、中心化、token 权重和控制协方差；
- 子空间估计器、rank 候选和正则项；
- 换基不变的投影、相似性和稳定性指标；
- frozen readout 的训练、验证和序列化规则；
- 对不同 $D_\ell$ 和 token topology 的处理；
- 数值退化、秩不足、近奇异协方差和缺失 token 的 typed failure。

### 4.3 解析与合成测试

至少建立以下 fixture：

1. 已知二维语义子空间在多个观测基之间旋转，投影应保持一致；
2. 语义信号分散在多个 head，单 head 失败而联合子空间成功；
3. 只有低级亮度变化，控制协方差应消除伪语义；
4. identity、线性层、残差加法和两分支路由具有解析传输结果；
5. semantic/complement 分解逐坐标恢复 complete-cut 总归因；
6. 刻意漏边、重复边、交换 Q/K/V slot 和错误 token 对齐必须被发现；
7. 注入、擦除、随机子空间和正交补干预有解析预期；
8. rank 过大、零差异、非有限值和 off-manifold 诊断触发明确终态。

### 4.4 N1 交付与准入

建议交付数学合同、closed schemas、实现骨架、标准库 metadata validator、测试和运行成本微基准。解析恒等式、mutation tests 和 determinism probe 全部通过后，才允许申请 N2。

## 5. N2：隔离 pilot 与测量可行性

### 5.1 pilot 数据边界

- 只使用 `pilot_discovery`，可包含历史已看样本，但必须登记；
- 不读取 confirmation 和 replication 图像；
- 只选择预先限定的少量层、rank 和语义轴；
- 所有因 pilot 被选择的概念、层、rank、readout 和剂量均进入选择日志。

### 5.2 输入行为门

在搜索内部机制前，先验证模型行为确实依赖候选语义因素。对 paired inputs 计算预定类别 margin 或任务输出：

$$
\Delta F_i^c=F_c(x_i^{c+})-F_c(x_i^{c-}).
$$

必须同时比较 null edit 和低级差异匹配对照。若 primary 模型对该因素没有达到最低行为效应，则该语义轴记为 `NO_BEHAVIOR_TO_EXPLAIN`，不继续内部搜索。该门只判断是否存在待解释行为，不是 NNS-CST 的支持证据。

### 5.3 子空间和 readout pilot

1. 提取少量注册层的 paired activations；
2. 比较 rank、中心化和控制协方差的数值稳定性；
3. 检查换基不变性和独立重算一致性；
4. 比较单 head、PCA、随机子空间和同容量 probe；
5. 估计 held-out 稳定性，但 pilot 结果仅用于设计；
6. 检查层间维数、token topology 和 CLS 处理是否一致。

### 5.4 NNS、传输与干预 pilot

- Endpoint 只用于成本和目标连通性测试；
- 对极小样本测试 Path NNS 收敛、reference 敏感性和 mask 对齐；
- 对一个合法 complete cut 测试 semantic/complement closure；
- 用 JVP 测试 attention、MLP 和 residual 的局部传输；
- 用少量剂量测试 paired injection/erasure 和 off-manifold 诊断；
- 记录每项任务 wall time、GPU-hours、峰值显存、输出大小和失败率。

### 5.5 N2 决策

允许的终态：

- `GO_PROTOCOL_FREEZE`：对象可估计、数值有效、行为门存在、预算可承受；
- `NO_GO_NO_BEHAVIOR`：没有待解释的输入行为；
- `NO_GO_NOT_IDENTIFIABLE`：语义和低级编辑效应无法分开；
- `NO_GO_SUBSPACE_UNSTABLE`：合理配置下子空间不可估计；
- `BLOCKED_INFRASTRUCTURE` 或 `INVALID_NUMERICAL`。

不能因 pilot 效果弱而遍历大量概念和层直到出现阳性。若需要改变 primary 语义轴，必须把原 pilot 封存，并用新的、尚未看过的 pilot 数据开始独立版本。

## 6. N3：正式协议、cohort、统计和预算冻结

### 6.1 必须冻结的字段

| 类别 | 必须冻结的内容 |
|---|---|
| 研究对象 | primary concept family、正负定义、margin、模型和 checkpoint |
| 数据 | 来源、许可、pair 生成、mask、split、source 去重和排除规则 |
| 注册位置 | layers、attention/MLP/residual edges、token 集合、CLS 处理 |
| 子空间 | estimator、rank、正则、中心化、token weights、readout |
| NNS | Endpoint 用途、Path reference、积分节点、收敛和完整切面 |
| 干预 | donor/recipient、注入/擦除、剂量、matched controls、有效性门 |
| claims | C1-C5 的 estimand、最小效应、检验方向和允许措辞 |
| 统计 | 独立单位、bootstrap/permutation、multiplicity、缺失和 NA |
| 资源 | GPU/CPU/wall/storage 上限、任务粒度、重试和停止规则 |
| 交付 | 原始数组、聚合表、审计子集、图表和 validator 覆盖 |

### 6.2 样本量和统计单位

- primary 独立单位为 source-level paired sample；
- 同一 source 的多个编辑、token、层、rank、剂量和随机对照随 source 一同重采样；
- 类别或概念层级结论需要相应数量的独立类别/概念，不能用大量同类图片代替；
- 功效分析围绕预注册最小实际效应和 family-wise decision，不能以 pilot 点估计直接当真值；
- 离散置换或符号翻转检验必须提前检查最小可达 p 值；
- 若样本量不足以同时检验全部 claims，应减少 confirmatory claims，而不是把不可达门留到结果阶段。

### 6.3 主 family 和决策

默认 formal family 为 C1-C4。C5 属于独立 replication family，只有 N8 获授权后才进入。

- C1 的 primary 比较是 semantic subspace 相对最佳预注册简单基线的 held-out 实际幅度；
- C2 的 primary 比较是 NNS 定位相对最佳预注册空间基线的 paired 优势；
- C3 的 primary 比较是预注册模块传输相对 identity/matched edge 的差异；
- C4 的 primary 比较是 semantic subspace 相对同秩同范数控制的双向、剂量化中介效应。

四项分别作阈值感知推断和 multiplicity 控制，不用“p<0.05 但低于实际幅度”换取支持。每项 `INVALID` 仍保留在 family 中。

### 6.4 冻结与授权

在任何 confirmation 图像解码或 outcome 访问前，封存：

- `protocol.json`；
- `claim_registry.json`；
- `cohort_manifest.json`；
- `pair_and_edit_registry.json`；
- `model_and_port_registry.json`；
- `subspace_and_readout_registry.json`；
- `nns_and_cut_registry.json`；
- `intervention_registry.json`；
- `statistical_analysis_plan.json`；
- `budget_and_schedule.json`；
- `protocol_freeze_receipt.json`。

文档写完不自动授权 N4。

## 7. N4：discovery/validation 学习与 confirmation seal

### 7.1 执行顺序

1. 验证 N3 全部 digest、当前代码 ancestry、环境和数据分割；
2. 只读取 discovery/train，提取冻结注册位置的 activations；
3. 拟合概念子空间、中心化参数和 frozen readout；
4. 只用 validation 从冻结候选中选择 rank 和有限超参数；
5. 执行随机标签、null pair、基旋转和重算测试；
6. 保存全部候选结果和选择轨迹，不只保存 winner；
7. 固化 $P_{\ell,c}$、readout、layers、thresholds 和 seeds；
8. 对 confirmation 文件清单和字节哈希签发 `confirmation_seal`。

### 7.2 禁止事项

- 不查看 confirmation activation、logit、map 或干预结果；
- 不按热图外观选层；
- 不把某个 SAE feature、head 或 channel 临时并入主对象；
- 不根据 validation p 值扩大候选池；
- 不把训练 accuracy 当作 C1 结果。

### 7.3 N4 准入

只有训练和选择过程可完整重放、confirmation seal 未破坏、所有 frozen objects 有唯一 identity 时，才允许申请 N5。子空间在 validation 中弱但数值有效时，可以继续做正式确认，也可以按预注册 futility 规则停止；不得主观挑选。

## 8. N5：held-out 表征确认与 NNS 输入/贡献生产

### 8.1 启动门

执行前记录：

1. local HEAD 和 tracking ref；
2. remote branch inclusion；
3. worktree porcelain v2；
4. Git LFS 状态；
5. 模型、数据、协议和 confirmation seal digest；
6. Python realpath、依赖、`CUBLAS_WORKSPACE_CONFIG` 和 GPU startup probe。

任何绑定失败均停在 N5，不读取 formal outcomes。

### 8.2 C1 生产

对全部 confirmation pairs 保存：

- 每层 projected coordinates 和 projection energy；
- frozen readout 输出；
- pair difference、稳定性和 nuisance diagnostics；
- 单 head、单 channel、PCA、随机子空间、probe 和范数基线；
- 每个 unit 的 terminal state 和资源。

不在 worker 中计算最终显著性，不按中间结果提前加样本或停止，除非 N3 已冻结 group-sequential rule。

### 8.3 C2 生产

1. 对冻结内部语义读出计算 Endpoint 开发对照和 Path NNS 正式图；
2. 保存 raw signed RGB/input-coordinate arrays；
3. 检查 Path 收敛、completeness、reference 和重复误差；
4. 在原生坐标上与真实编辑 mask 对齐；几何增强先逆变换；
5. 计算像素差、attention、梯度范数、中心/面积和低级特征基线；
6. 使用固定区域替换验证 NNS 定位，而不是重新挑选最有利区域。

### 8.4 完整贡献生产

- 对预注册 complete cuts 计算 semantic/complement NNS conductance；
- 验证每条有效输入到目标路径恰好穿过一个 cut edge；
- 重算 semantic + complement = component，components = total IG；
- 分别保存 attention、MLP、identity/residual 和 CLS 分量；
- 不跨层相加，不用 source-summed 数据声称恢复了已丢失坐标。

### 8.5 N5 终态

N5 只完成表征与贡献数据，不提前将 C3/C4 记为支持。若 C1 的预注册 futility 规则明确判断不存在可用子空间，则停止，不进入 N6；这是科学止损，不是基础设施失败。

## 9. N6：子空间干预与模块传输

### 9.1 干预对象

对 N4 冻结的 $P_{\ell,c}$，使用 N3 冻结的 paired donor/recipient 和剂量，分别运行：

- positive-to-negative injection；
- positive-side erasure；
- full paired activation patching 上限；
- 同秩同范数随机、PCA、正交补、单 head 和错配 donor；
- 非目标概念 matched intervention。

严禁根据 N5 的层效应重新选择干预层。若允许分阶段层选择，选择规则必须已在 N3 中定义，并使用与 N6 效应估计独立的数据。

### 9.2 C3 局部传输

对预注册 attention、MLP 和 residual edge：

1. 用 JVP 计算 $\mathcal T_{e,c}$ 对真实 paired semantic perturbation 的局部预测；
2. 测量进入下一层语义子空间的保持、增益、泄漏和 CLS 迁移；
3. 与 identity、matched random edge 和参数随机化对照比较；
4. 用有限 activation patching 检查局部预测方向；
5. 对理论等价切面要求恢复相等，而不是要求可区分。

### 9.3 C4 有限中介

每个 dose 同时记录：

- downstream semantic readout；
- primary class margin；
- 预注册非目标 margins；
- clean prediction 与 top-k stability；
- activation norm、LayerNorm statistics、非有限值和异常距离；
- 与 full paired patching 的相对恢复率。

必要性和充分性分别判定，之后再形成 C4。擦除有效、注入无效时只能写成必要性证据；反之只能写成有限充分性证据。单剂量显著但剂量合同失败时不能升级为完整因果中介。

### 9.4 有效性与恢复

- 数值、形状、模型绑定、任务覆盖和干预流形诊断是硬门；
- 科学方向与剂量结果不是恢复依据；
- worker 或 manifest 故障可在 fresh root 中只重跑受影响任务；
- 已验证的 activation 和 NNS 数组可通过内容哈希继承，避免无意义 GPU 重算；
- 所有失败 attempt 保留。

## 10. N7：CPU-only 分析、独立审计和逐主张裁定

### 10.1 运行边界

设置 `CUDA_VISIBLE_DEVICES=''`，不导入 Torch/timm，不加载模型，不解码 JPEG，不生成新 outcome。只读取封存数组、metadata、masks 和日志。

### 10.2 独立重算

validator 从原始记录重算：

- source/pair/split coverage；
- subspace orthogonality、rank 和换基不变性；
- C1 全部 held-out 效应和基线；
- C2 mask 对齐、变换一致性和区域干预；
- semantic/complement 和 complete-cut closure；
- C3 传输、JVP 与有限 patching 对照；
- C4 注入/擦除剂量、特异性和副作用；
- bootstrap/permutation、CI、multiplicity 和状态 truth table；
- GPU-hours、CPU-hours、wall time、峰值显存和存储。

浮点派生量使用协议规定的容差，不用 JSON 严格相等误判约 $10^{-15}$ 的重算差异。离散 ID、hash、状态和计数仍要求精确相等。

### 10.3 结果表

必须交付：

| 表 | 最低字段 |
|---|---|
| claim decisions | claim、n、estimate、CI、threshold、adjusted p、validity、state |
| representation | source pair、layer、rank、semantic/control scores、baselines |
| grounding | source、mask、method、alignment、region intervention、geometry |
| contribution | cut、edge、semantic/complement、closure、cancellation |
| transport | module、local prediction、finite effect、identity/control comparison |
| intervention | source、layer、dose、direction、target/non-target effects、validity |
| terminal accounting | planned/completed/failed/invalid units and reasons |
| claim ledger | required evidence、observed result、allowed wording、artifact path |

### 10.4 裁定

C1-C4 分别签发 `SUPPORTED`、`ASSOCIATIONAL`、`NOT_SUPPORTED`、`INCONCLUSIVE` 或 `INVALID`。不得用一个 omnibus 失败覆盖局部有效发现，也不得用一个局部支持把整套方法写成已验证。

独立方法论文准入使用[研究目标](研究目标.md)中预先写定的组合：C1 和 C4 必须支持，并且 C2/C3 至少一项支持。未达到时，N8 只能做阴性总结或范围收缩，不能更换定义继续追阳性。

## 11. N8：独立复现、工具交付和论文定位

### 11.1 进入条件

只有 N7 有效完成后才讨论 N8。若独立方法论文最低门没有达到，默认不执行昂贵复现；可选择发布技术报告或保留方法学阴性结果。

### 11.2 复现设计

在读取第二模型 outcome 前冻结：

- 模型和 checkpoint；
- 层深对应方式；
- 子空间 rank 规则，而不是固定相同数值；
- 主语义 family 和 pairs；
- 机制层级预测；
- 复现效应和容差。

跨模型比较投影、canonical correlations、层深区间和模块作用，不比较任意基向量编号。第二模型数值无效时，C5 为 `INVALID`，第一模型结果仍按原范围保留。

### 11.3 工具交付

工具至少包括：

1. paired counterfactual registry；
2. semantic-subspace estimator 和 frozen readout；
3. basis-invariant diagnostics；
4. Endpoint/Path NNS input grounding；
5. semantic/complement complete-cut accounting；
6. low-rank JVP transport；
7. paired injection/erasure runner；
8. independent validators 与 claim-gated report。

工具界面不得自动把清晰热图、probe 高准确率或一次干预转写为“编码”“专门化”或“因果机制”。

### 11.4 论文定位

若最低门通过，论文主线为：

> NNS-CST 以配对反事实识别分布式视觉语义子空间，用 NNS 将其连接到输入和完整决策贡献，并通过跨层传输与双向有限干预检验其机制作用。

如果只支持 C1，定位为分布式表征分析。

如果支持 C1+C2，定位为输入落地的语义表征工具。

如果 C4 不支持，不得使用“causal semantic transport”作为已验证结论，只能作为被检验的方法框架。

如果 C1 也不支持，停止该路线，不以审计能力包装成独立语义解释方法。

## 12. 图表规划

只有结果对应主张有效时才生成论文图，不预先承诺阳性叙事。建议图组：

1. **方法图**：配对语义变化、子空间、NNS 输入图、传输和干预五部分；
2. **表征图**：全层子空间维数、稳定性及相对基线优势；
3. **输入定位图**：原图、编辑 mask、Endpoint 开发图、Path NNS 正式图和区域干预；
4. **传输图**：attention/MLP/residual 的语义保持、增益、泄漏和 CLS 迁移；
5. **因果图**：注入/擦除剂量曲线及非目标副作用；
6. **完整记账图**：semantic/complement、module components 和 total IG 的闭合；
7. **复现图**：第二模型的预注册机制效应，而非挑选相似案例。

展示图保留共同色标、原始符号和固定样本选择。每张图附 provenance 和逐图说明；display transforms 不进入统计。

## 13. 停止规则

以下任一情况触发相应停止：

- N0 发现直接重复且无可验证差异：`NO_GO_NOVELTY`；
- 无可靠 paired counterfactual：`BLOCKED_DATA`；
- 语义与低级编辑不可识别：`BLOCKED_IDENTIFIABILITY`；
- 输入行为门不存在：`NO_BEHAVIOR_TO_EXPLAIN`；
- 子空间在合理配置下不可稳定估计：`NO_GO_SUBSPACE_UNSTABLE`；
- formal C1 不支持且 futility 条件成立：不进入 N6；
- 干预普遍越出有效激活范围：`INVALID_INTERVENTION`，先诊断而非解释方向；
- C1/C4 未达到独立论文门：不做大规模跨架构生产。

停止不意味着删除数据或失败 root。所有有效阴性、无效原因和资源记录进入最终 handoff。
