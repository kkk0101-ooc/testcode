# S4-R4 prospective serialization-recovery amendment

This amendment is frozen after S4-R3 launch-001 exposed a systematic implementation defect and before any implementation change or recovery launch. Two NNS units completed valid numerical integration through the frozen 256-step closure, then published `FAILED_IMPLEMENTATION` because the P2 coordinate-plan JSON publisher passed a NumPy `int64` to the standard JSON encoder. Their four dependent occlusion placeholders correctly published `NA_UPSTREAM_NNS`. Six other workers were still computing their first NNS units and had no terminal. Continuing the launch would deterministically repeat the same post-compute serialization failure across the cohort, so only the eight S4-R3 worker PIDs are prospectively terminated; unrelated coexisting compute PIDs are not touched. The launch, claims, logs, arrays, failed terminals, and upstream-NA terminals remain immutable evidence.

S4-R4 changes only the P2 coordinate-plan serialization boundary: the document is recursively normalized to JSON-native scalars and arrays before canonical digesting and atomic publication. It also moves production evidence and large payloads to fresh roots `evidence/nns_vit_patch_depth/s4_r4_20260915/` and `artifacts/nns_vit_patch_depth/s4_r4_20260915/`. The selected cache is not read before the new implementation is committed, pushed, sealed in a second commit, pushed again, and verified on the live remote branch. After that gate, S4-R3 cached selected-member bytes may be SHA/bytes/geometry revalidated and rebound without rereading archive members; all failed or unterminated S4-R3 compute units are recomputed in the fresh root.

No cohort, order, target, component, numerical contract, quadrature schedule, P1/P2 definition, control matching, operator, typed failure, seed, retention, or scientific boundary changes. S3 D2 prediction/error values remain forbidden. Cost and elapsed time remain reporting-only.
