# S4-R10 final pre-interim seal amendment

S4-R9 was never sealed and never used for an interim; formal P1/P2/D1 aggregate access remained zero. S4-R10 regenerates every pre-interim artifact after the final within-class whole-image BCa implementation and the direct rebind/stale-claim recovery tests. It changes no cohort, look, threshold, direction, alpha spending, closed-testing rule, validity gate, matching gate, or power gate. S4-R5 through R9 remain immutable pre-seal drafts. S4-R10 is the only production-authorized group-sequential root after its two-step remote implementation seal is complete.

The `_v3` and `_v4` pre-seal validation reports were generated before the final R10 closed-schema, typed INVALID/BLOCKED adjudication, interruption-lock validation, numeric-validator files, and report-binding code were published as one implementation tree. They remain immutable superseded evidence. After that implementation tree is live on the remote, the implementation seal binds the prospectively generated `_v5` reports only. No efficacy aggregate or interim result was accessed in any generation.

Fresh recovery launches write arrays below a launch-specific payload namespace. An immutable terminal selects the authoritative launch payload; arrays from a crashed claim remain intact and are never overwritten by a later launch. This is an engineering retention hardening only and changes no numeric method.

An idle worker polls while any unresolved claim belongs to a live worker, so it can immediately consume occlusion units when their NNS dependency becomes terminal. Claims owned by dead workers remain immutable evidence and do not keep healthy workers waiting; a fresh launch retries only those missing units.

Every look must publish an independent CPU-only numeric-validation receipt before the interim adjudicator can open current-look endpoint values. Look completion also requires one immutable source-completion record per authorized image.
