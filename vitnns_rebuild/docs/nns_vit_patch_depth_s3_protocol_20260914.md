# NNS ViT patch-depth S3 prospective protocol

This document freezes S3 before any formal probe-train, probe-validation, or D2-test image/mask byte access. The only predecessor is S2-R8 PASS at commit 7b8dd924ee0160e7ca61796b266d840da34d4ed0; the only selected D2 manifest is candidate_m4_manifest.json with 3,482 images and cap 4.

S3 performs frozen ViT representation extraction for 5,232 train images and 1,744 validation images, train-only class-conditional ridge fitting, validation-only alpha selection, train-only three-fold cross-fit diagnostics, a committed and remotely verified weight seal, and then representation extraction plus per-image/per-block prediction for 3,482 D2 test images. Every source image is one queue unit and one frozen-backbone forward captures all twelve post-block patch-token outputs. S3 does not run NNS, attribution, occlusion, P1, P2, S4, or S5 and does not materialize a D2 deep-minus-shallow endpoint or any cohort-level scientific inference.

Train-only normalization is the float64 population mean and population standard deviation (ddof=0) over all 6 equally weighted images and their 196 equally weighted patches; exact zero scales become one. Ridge uses an unregularized intercept and a centered primal symmetric eigendecomposition reused over alpha [0.01, 0.1, 1, 10, 100]. Validation uses the arithmetic mean of the two per-image patch MSEs. The smallest MSE wins, with smallest numeric alpha as the exact tie-break. The final fit remains the original six train images. The low-level control uses only row-major [x,y,R_mean,G_mean,B_mean] with patch-center coordinates and pre-model-normalization RGB in [0,1].

Cross-fit ordering is SHA-256 of NNS_VIT_PATCH_DEPTH_S3_D2_TRAIN_CROSSFIT_V1, NUL, annotation WNID, NUL, source image ID, then source ID as tie-break. Ranks 0-1, 2-3, and 4-5 form folds 0, 1, and 2. Each fold fits normalization and weights on the other four images and predicts the held-out two using the already validation-selected alpha. Cross-fit never changes a formal choice.

The pre-access implementation seal must be committed, pushed, and visible at the remote branch before train/validation access. The independently validated probe weight seal and test-access gate must likewise be committed, pushed, and remotely visible before any selected D2 JPEG or mask member access. Test access then recomputes both archive hashes before reading only selected members. Test features, predictions, and per-block errors are retained per image; no cohort aggregation is authorized.

Each launch scans H20 eligibility once, selects exactly min(8, |E|) in physical-index/UUID order, records coexisting compute PIDs without automatically excluding them, obtains UUID-keyed atomic locks, and starts one long-lived worker per GPU. Claims are launch-specific atomic files; completion is a global immutable terminal keyed by schedule index and source identity. Healthy workers continue after another worker fails. Recovery uses a fresh launch and only missing terminals; old claims remain evidence but never block recovery.

Cost and elapsed-time projections only inform engineering. They cannot reduce the cohort or create budget/wall-time/cost terminal states. PASS authorizes only S4_NNS_AND_OCCLUSION_EXECUTION_ONLY; any other S3 terminal authorizes nothing.
