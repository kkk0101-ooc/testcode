# S3-R4 prospective scalar-serialization recovery amendment

Post-test numeric validation found that the generic array writer called NumPy ascontiguousarray on the per-image float64 low-level-control MSE. NumPy promotes a zero-dimensional input to shape [1], while the frozen S3 contract requires a float64 scalar with shape []. All S3-R3 values are finite and numerically correct, and every other array contract passed, but the serialized shape makes S3-R3 ineligible for PASS. S3-R3 terminals and payloads remain immutable evidence.

S3-R4 is a fresh recovery root. It does not read JPEG or mask bytes, decode images, load the model, extract features, fit or alter weights, select alpha, or aggregate test errors. It rebinds each of the 10,458 S3-R3 source terminals and all valid arrays after SHA-256 and canonical-array verification. For each of the 3,424 VALID D2 units only, it loads that image's sealed occupancy and low-level prediction, recomputes the same per-image patch MSE in float64, and writes it as a true zero-dimensional little-endian float64 NPY under a fresh S3-R4 payload root. It then creates one fresh immutable S3-R4 terminal per scheduled source. Typed-NA units remain typed NA without replacement.

The generic writer is prospectively repaired by preserving zero-dimensional arrays and only making non-contiguous arrays contiguous. The weight seal, alpha choices, normalization, probes, cohort, missingness, predictions, access counts, and scientific contracts do not change. No cohort-level D2 endpoint or inference is computed. The recovery runs CPU-only and has zero additional formal image/mask/member access.
